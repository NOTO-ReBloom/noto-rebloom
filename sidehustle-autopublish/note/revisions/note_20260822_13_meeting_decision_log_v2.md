## 新タイトル
学生団体の会議を「決めただけ」で終わらせない｜コピペできる決定ログ＋宿題管理テンプレ

## 無料部分

会議で話した内容をきれいに残しているのに、次の会議で「これ誰がやるんだっけ」「結局決まったんだっけ」が起きる。

この状態なら、議事録を長くするより、**会話の記録と“実行するための記録”を分ける**方が効きます。

まず、前回の議事録を1つ開いて、次の4つが30秒で見つかるか確認してください。

- 何を決めたか
- 誰が動くか
- いつまでか
- 未完了なら次にどうするか

1つでも探さないと分からないなら、議事録は「読める文章」にはなっていても「仕事を進める道具」にはなっていません。

### 例：同じ会議でも、残し方でここまで変わる

**Before**

> 協賛企業への報告について話し合った。写真をまとめて来週中に送る方向。

この文章だと、担当・期限・完成条件がありません。

**After**

|決定|担当|期限|完了条件|次回確認|
|---|---|---|---|---|
|A社へ開催報告を送る|田中|10/20 18:00|写真3枚＋参加人数＋お礼文をメール送信|10/21定例|

これなら、会議に出ていない人でも次の行動が分かります。

無料部分でやることは1つだけです。**前回議事録から「決定」「担当」「期限」の3列だけ抜き出してみてください。**

ここから先では、その3列を実際に回る仕組みにするために、決定ログ・宿題ログ・保留ログの3枚と、記入例、未完了時の処理、AIで議事録から抜き出すプロンプトまでまとめます。

## 有料部分

# 1. まず3つのログに分ける

会議で出た内容を全部1枚へ押し込むと、決定・作業・保留が混ざります。分けるのは次の3種類です。

### A. 決定ログ

「何を決めたか」と「なぜそう決めたか」を残します。

コピー用：

```
決定ID：
決定日：
議題：
決定内容：
決定理由：
適用範囲：
見直す条件：
関連資料：
決定者：
```

**記入例**

```
決定ID：D-2026-018
決定日：2026/10/16
議題：イベント参加費
決定内容：一般500円、学生無料
決定理由：会場費を一部回収しつつ学生参加の障壁を下げる
適用範囲：11月開催分
見直す条件：申込が30人未満／会場費変更
関連資料：予算表v3
決定者：実行委員長
```

「なぜ」を1行残すのがポイントです。半年後に条件が変わった時、結論だけ残っていると同じ議論を最初からやり直します。

# 2. 宿題ログは“完了条件”まで書く

「資料を作る」では、どの状態なら終わりか人によって違います。

コピー用：

|タスク|担当|期限|完了条件|依存先|状態|次回確認|
|---|---|---|---|---|---|---|
| | | | | |未着手| |

状態は **未着手／進行中／確認待ち／完了／中止** の5つで十分です。

### 悪いタスク
協賛資料を作る

### 良いタスク
A社へ送れるPDFを完成させ、共有フォルダ「協賛/送付版」に格納する

後者なら、担当者が変わっても完了判定ができます。

# 3. 保留ログを作る

「今日は決められない」は問題ではありません。危ないのは、何が揃えば決められるのか分からないまま消えることです。

コピー用：

|保留事項|決められない理由|不足情報|確認担当|回答期限|再検討日|
|---|---|---|---|---|---|
| | | | | | |

**記入例**

|保留事項|決められない理由|不足情報|確認担当|回答期限|再検討日|
|---|---|---|---|---|---|
|雨天時の会場変更|代替会場の空き不明|体育館の空き・料金|佐藤|10/18|10/18 21:00|

保留を「止まった仕事」ではなく、**次の判断条件が決まった仕事**にします。

# 4. 会議の最後5分だけ、この順で読む

会議の終盤で新しい議論を始めず、最後の5分を固定します。

1. 今日の決定を読む
2. 新しい宿題を読む
3. 担当と期限を本人に確認する
4. 保留事項の不足情報と再検討日を確認する
5. 次回冒頭で確認するタスクを決める

この5つを読み上げた時点で、担当不明・期限不明があればその場で埋めます。

# 5. 次回会議は“新しい議題”から始めない

冒頭5分で前回の宿題を次の4つに分けます。

- 完了
- 進行中
- 期限変更
- 中止

期限変更が2回続いたら、単純に締切を延ばす前に次を確認します。

### 未完了の切り分け

**A. タスクが大きすぎる**
→ 30〜60分で終わる単位まで分割

**B. 他人の返答待ち**
→ 「確認待ち」に変更し、次回連絡日を設定

**C. 権限がない**
→ 誰の承認が必要かを記録

**D. やる意味が分からない**
→ 元の決定ログへ戻り、目的・理由を確認

**E. 優先度が下がった**
→ 中止または保留にして、幽霊タスクとして残さない

# 6. 1枚で始めたい人向け統合版

3表に分けるのが面倒なら、最初の2週間はこの列だけでも構いません。

|種類|内容|担当|期限|完了条件/再判断条件|状態|次回確認|
|---|---|---|---|---|---|---|
|決定| | | | | | |
|宿題| | | | | | |
|保留| | | | | | |

種類を「決定／宿題／保留」から選ぶだけです。

# 7. AIで議事録から抜き出すコピペ用プロンプト

ChatGPT・Claude・Geminiなどへ会議メモを渡せる環境なら、次を使えます。機密情報・個人情報は所属組織のルールに従い、必要なら匿名化してください。

```
以下の会議メモを、会話の要約ではなく「次の仕事が進む記録」に整理してください。

出力は4つに分けてください。

1. 決定事項
- 決定内容
- 決定理由（メモに根拠がある場合だけ）
- 適用範囲
- 見直し条件

2. 宿題
- タスク
- 担当
- 期限
- 完了条件
- 依存先

3. 保留
- 保留事項
- 決められない理由
- 不足情報
- 確認担当
- 再検討日

4. 不明点
担当・期限・理由など、元メモに書かれていない情報は推測せず「未確認」と表示してください。

会議メモ：
---
ここに貼る
---
```

AIが担当や期限を勝手に補完した場合は採用しません。「未確認」が出る方が安全です。

# 8. 15分で導入する手順

**0〜3分**
共有できる表を1つ作る。

**3〜7分**
前回会議から決定・宿題・保留を最大5件だけ移す。

**7〜10分**
担当・期限・完了条件の空欄を確認する。

**10〜12分**
次回会議の冒頭5分に「前回タスク確認」を入れる。

**12〜15分**
メンバーへ「今後、会議終了前にこの表だけ確認する」と共有する。

最初から過去1年分を移行する必要はありません。今日以降の会議だけで始めます。

# この仕組みが向かない場合

- 2人だけで常に隣で作業し、その場で全部完了する
- タスク管理ツールですでに担当・期限・完了条件が徹底されている
- 会議自体が意思決定の場ではなく、雑談・アイデア出しだけ

この場合、ログを増やす方が負担になります。

# まとめ

良い議事録は、長い議事録ではありません。

- 決定は「理由」まで
- 宿題は「担当・期限・完了条件」まで
- 保留は「何が揃えば決められるか」まで
- 次回冒頭で前回の未完了を確認する

この4つが回れば、会議の内容を思い出すためではなく、**会議で決めたことを実行するための記録**になります。
